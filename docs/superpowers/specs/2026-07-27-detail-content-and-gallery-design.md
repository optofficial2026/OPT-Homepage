# 상세 페이지 콘텐츠·갤러리 개선 설계

## 목표

활동·세미나·해커톤 상세 페이지에서 글의 위계를 명확하게 만들고, 관리자가 어려운 URL 입력 없이 상세 사진을 최대 5장까지 올릴 수 있게 한다.

## 변경 대상

- 활동 상세와 활동 기록 편집
- 세미나 상세와 세미나 편집
- 해커톤 상세와 해커톤 편집
- 상세 페이지 공통 구역·갤러리 스타일
- 이미지 입력 안내 문구

Supabase의 기존 `galleryUrls` 배열과 `detail` JSON 구조를 그대로 사용하므로 데이터베이스 마이그레이션은 하지 않는다.

## 관리자 이미지 입력

### 용어

- **목록 썸네일:** 활동 기록 또는 아카이브 목록 카드에 보이는 작은 사진
- **상세 대표 이미지:** 상세 페이지 제목 아래에 크게 보이는 한 장
- **상세 사진:** 상세 본문에 보이는 사진 묶음, 최대 5장
- **관련 링크:** GitHub, 데모, 발표 자료처럼 새 창으로 여는 외부 페이지

각 입력 아래에 실제 노출 위치와 권장 용도를 한 문장으로 표시한다. `슬러그`는 `주소 이름 (영문)`으로 바꾸고 영문 소문자·숫자·하이픈만 가능하다는 예시를 제공한다.

### 단일 이미지

목록 썸네일과 상세 대표 이미지는 URL 텍스트 입력을 숨기고 다음 UI로 교체한다.

- 현재 이미지 미리보기
- `사진 선택` 버튼
- 현재 이미지를 비우는 `삭제` 버튼
- JPEG, PNG, WebP 및 장당 5MB 제한 안내

기존 URL 값은 숨은 폼 값으로 보존하므로 과거에 등록한 사진도 그대로 편집할 수 있다.

### 상세 사진

활동·세미나·해커톤 편집 폼이 같은 다중 이미지 입력을 사용한다.

- 파일 선택 창에서 여러 장 동시 선택
- 기존 사진을 포함해 최대 5장
- 선택 순서대로 미리보기
- 각 사진을 개별 삭제
- 남은 업로드 가능 수 표시
- JPEG, PNG, WebP 및 장당 5MB 제한
- 5장을 넘으면 저장하거나 추가 업로드하지 않고 명확한 오류 표시
- 저장 시 기존 `galleryUrls` 배열에 미리보기 순서대로 기록

관리자에게 노출되던 `갤러리 URL (한 줄에 하나)` 입력칸은 제거한다.

## 상세 페이지 정보 구조

모든 콘텐츠 구역은 공통 에디토리얼 형식을 사용한다.

- 청록색 영문 번호 라벨
- 명확한 한글 소제목
- 구역 상단 구분선
- 제목과 본문 사이의 일정한 여백
- 읽기 폭을 제한한 본문
- 콘텐츠가 비어 있으면 소제목은 유지하고 `준비 중입니다.` 표시

### 활동

1. `01 / CONTENT` — 활동 내용
2. `02 / GALLERY` — 활동 사진

### 세미나

1. `01 / CONTENT` — 세미나 내용
2. `02 / GALLERY` — 세미나 사진
3. `03 / RESOURCE` — 관련 자료

### 해커톤

기존 순서와 의미를 유지하며 다음 10개 구역을 항상 표시한다.

1. 문제
2. 해결
3. 주요 기능
4. 프로젝트 화면
5. 개발 과정
6. 시스템 구조
7. 회고
8. 결과
9. 기술 스택
10. 팀

외부 링크 버튼은 현재 위치를 유지한다. 링크가 하나도 없으면 `준비 중입니다.`를 표시한다.

## 사진 표시

- 상세 대표 이미지는 본문 시작 전에 큰 가로 이미지로 표시한다.
- 대표 이미지가 없으면 `대표 이미지 준비 중입니다.` 플레이스홀더를 표시한다.
- 상세 사진은 데스크톱 2열, 모바일 1열로 표시한다.
- 사진은 동일한 비율과 둥근 모서리를 사용하되 구역 제목과 구분선으로 본문과 분리한다.
- 최대 5장까지만 렌더링한다.

## 글자 크기

- 상세 제목: `clamp(40px, 6vw, 72px)`
- 구역 소제목: `clamp(26px, 3.5vw, 40px)`
- 본문: `clamp(16px, 1.4vw, 19px)`, 줄간격 `1.8`
- 날짜·기수·구역 번호: `12px`에서 `14px`
- 모바일 상세 제목 최대 `48px`
- 모바일 구역 소제목 최대 `30px`

현재의 큰 제목 분위기는 유지하되 제목·소제목·본문 사이의 크기 차이를 줄이고, 긴 제목은 자연스럽게 줄바꿈한다.

## 오류와 저장

- 업로드 실패 시 이미 저장된 사진과 성공한 업로드는 유지하고 오류 문구를 표시한다.
- 저장 실패 시 편집창을 닫지 않아 입력 내용을 보존한다.
- 사진을 삭제해도 저장 버튼을 누르기 전까지 공개 페이지 데이터는 바뀌지 않는다.
- 공개 상세 페이지에서는 오래된 데이터가 5장을 초과하더라도 앞의 5장만 표시한다.

## 검증

- 다중 이미지 입력이 최대 5장을 강제하는지 자동 테스트한다.
- 세 편집 폼이 URL textarea 대신 공통 상세 사진 입력을 사용하는지 확인한다.
- 세 상세 페이지의 모든 소제목과 `준비 중입니다.` fallback을 확인한다.
- 상세 전용 글자 크기와 구분 스타일을 회귀 테스트한다.
- 전체 테스트, TypeScript 검사, 루트와 GitHub Pages base 빌드를 실행한다.
- 관리자 로그인 상태에서 활동·세미나·해커톤의 사진 업로드·삭제·저장을 실제로 확인한다.
- 공개 페이지에서 데스크톱과 모바일 레이아웃을 확인한다.
